# bootSamples — модуль simpleDao (блокнот баллов)

Репозиторий содержит один Gradle-модуль **`simpleDao`** — веб-приложение «Блокнот баллов»: очередь задач, журнал выполненных действий, сумма баллов и сохранение в БД (H2 локально или PostgreSQL в Docker). Образ Docker собирается **только из `simpleDao/`** (`docker-compose.yml` в корне).

---

## Что делает программа

- **Очередь задач** (`pending_tasks`): вы задаёте текст и положительную величину баллов; задача появляется в списке активных.
- **Закрытие задачи**: для каждой строки — кнопки **«Готово»** (в журнал попадает **+N**) или **«Не готово»** (**−N**).
- **Журнал** (`event_records`): только уже закрытые задачи; можно удалить строку из журнала.
- **Счёт** в шапке страницы с подсветкой: меньше нуля — красный, от 0 до 99 — жёлтый, от 100 и выше — зелёный.
- При запуске через **Docker Compose** Hibernate создаёт таблицы в PostgreSQL; дополнительный SQL добавляет комментарии к столбцам и представления **`v_journal_for_ui`** / **`v_tasks_queue_for_ui`** для удобного просмотра в Adminer.

## Требования

| Компонент | Версия / примечание |
|-----------|---------------------|
| **JDK** | **25** (toolchain в Gradle; без него сборка подставит JDK 25 автоматически, если установлен) |
| **Docker** и **Docker Compose** | Для варианта «всё в контейнерах» |
| **Браузер** | Любой современный |

Локальный запуск без Docker использует **встроенную H2** (файл базы в каталоге приложения; см. `.gitignore` для `simpleDao/data/`).

## Запуск

### Вариант A — Docker Compose (PostgreSQL + приложение + Adminer)

Из корня репозитория (`bootSamples`):

```bash
docker compose up --build
```

После старта:

| Сервис | Адрес |
|--------|--------|
| Приложение | http://localhost:8090 |
| Adminer (просмотр БД) | http://localhost:5050 |
| PostgreSQL | `localhost:5432`, БД `notebook`, пользователь `notebook`, пароль `notebook` |

Подключение к PostgreSQL из контейнера приложения уже настроено профилем **`docker`**.

Остановка: `Ctrl+C` или в другом терминале:

```bash
docker compose down
```

Данные Postgres сохраняются в томе Docker (`pg_data`), пока том не удалять.

### Вариант B — только приложение из IDE / Gradle (H2)

Из корня репозитория:

```bash
./gradlew :simpleDao:bootRun
```

Или запуск главного класса **`w2l.inspired.Main`** в модуле **simpleDao**. Профиль **`docker` не активируется** — используется `application.properties` и H2.

Консоль H2 (если включена в `application.properties`): путь вида `/h2-console`.

## Рекомендации

1. **Коммит**: не добавляйте каталоги **`build/`**, **`.gradle/`**, локальную папку **`simpleDao/data/`** (H2) — они в `.gitignore`. Каталог **`.idea/`** больше не отслеживается Git’ом (локальные настройки IDE остаются только у вас).
2. Если после сборки в Docker каталог **`simpleDao/build/`** не удаляется (`Отказано в доступе`), часть файлов могла создаться от **root**. Удалите вручную:  
   `sudo rm -rf simpleDao/build`  
   либо выполните **`./gradlew :simpleDao:clean`** под своим пользователем (если права позволяют).
3. **Docker**: после изменения Java-кода пересобирайте образ: `docker compose build app` или `docker compose up --build`.
4. **Просмотр «готовых» задач в БД**: в Adminer выберите базу **`notebook`**, затем представление **`v_journal_for_ui`** или таблицу **`event_records`** → «Выбрать данные».
5. **Порты заняты**: поменяйте проброс в `docker-compose.yml` или переменную **`ADMINER_PORT`** для Adminer.

## Структура (важное для simpleDao)

```
simpleDao/
├── Dockerfile
├── build.gradle
├── src/main/java/w2l/inspired/    # Spring Boot, JPA, контроллеры
├── src/main/resources/
│   ├── application.properties      # локально: H2
│   ├── application-docker.properties
│   ├── db/postgres-ui-help.sql    # комментарии и VIEW для PostgreSQL
│   ├── templates/notebook.html
│   └── static/styles.css
docker-compose.yml                  # в корне bootSamples
```

Корневой **`settings.gradle`** подключает только **`simpleDao`**; **`build.gradle`** в корне — лёгкий агрегатор без зависимостей приложения.
